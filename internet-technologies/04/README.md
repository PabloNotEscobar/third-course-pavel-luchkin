# Занятие 4. HTTP-методы, REST и CRUD

Как запустить: открыть index.html в браузере. Сборка и сервер не нужны, нужен только интернет.

API: https://jsonplaceholder.typicode.com/posts (учебный сервис, изменения на сервере не сохраняются).

Реализованные методы:
GET /posts?_limit=10 (загрузка)
POST /posts (создание)
PATCH /posts/:id (редактирование)
DELETE /posts/:id (удаление)

Состояние: объект state в app.js. Поля posts, isLoading, isSaving, error (загрузка), saveError (сохранение и удаление), formError (валидация формы), editingId (null это создание, число это редактирование записи с таким id), filter. Интерфейс целиком строится функцией render() из state. Карточки в DOM напрямую не меняются.

Ошибки: все запросы идут через sendRequest(), который бросает Error при response.ok равном false. Ошибка загрузки показывается над списком, ошибка сохранения или удаления под формой, пустые поля отсеиваются до запроса. Пока идёт запрос, isSaving блокирует кнопки и повторную отправку формы, поэтому быстрые клики не создают дубли.

Что происходит после успешного ответа:
POST: возвращённый объект добавляется в начало state.posts.
PATCH: соответствующий объект в state.posts заменяется обновлённым, форма возвращается в режим создания.
DELETE: запись убирается из state.posts фильтром.
После каждой операции вызывается render().

Особенность API: на каждый POST JSONPlaceholder возвращает id 101. Чтобы у новых записей в state не было одинаковых id, приложение выдаёт следующий свободный. Такой записи на сервере нет, поэтому PATCH для неё может вернуть ошибку 500, и она показывается под формой.

Почему изменения пропадают после перезагрузки: сервис принимает запросы и возвращает правдоподобные ответы, но ничего не записывает в базу. Список заново приходит с сервера в исходном виде.

Фильтрация: по title и body, по уже загруженному state.posts, без новых запросов.
