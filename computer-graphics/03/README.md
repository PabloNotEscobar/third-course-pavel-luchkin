# Занятие 3. Окружность: алгоритм средней точки

Как запустить: открыть index.html в браузере. Кнопки с примерами строят окружности из задания, в том числе одну с выходом за границы области.

Как используется симметрия: алгоритм вычисляет только базовые точки (x, y). Функция plot8 из каждой такой точки рисует сразу восемь: (x, y), (y, x), (-x, y), (-y, x), (x, -y), (y, -x), (-x, -y), (-y, -x), сдвинутых на центр. Режим "Показать симметрию шага" (или клик по строке таблицы) выделяет красным восемь точек одного шага, синим базовую.

Почему достаточно одной восьмой: окружность симметрична относительно осей и диагоналей, поэтому сектор от верхней точки до направления 45 градусов повторяется восемь раз.

Переменная d: решающая величина. Это значение функции окружности в средней точке между двумя кандидатами E и SE, сдвинутое на константу 1/4, чтобы остались только целые числа. Начальное значение 1 - r.

Когда уменьшается y: при d >= 0 выбирается SE, y уменьшается на 1. При d < 0 выбирается E, y остаётся прежним.

Почему цикл идёт до x > y: при x = y мы дошли до границы сектора в 45 градусов, дальше точки были бы отражением уже построенных.

Выход за границы: пиксели вне области 40 на 30 не рисуются, остальная часть строится, над холстом показывается предупреждение с числом скрытых пикселей. Радиус должен быть целым и больше 0.

Сравнение с формулой y = round(sqrt(r² - x²)): пиксели совпали на всех радиусах из таблицы на странице (1, 2, 3, 5, 8, 10, 15, 20, 30, 50, 100, 200). Дополнительно проверил все радиусы от 1 до 2000, различий нет. Количество базовых точек у обоих способов одинаковое.

Эксперимент по времени (кнопка "Замерить", 5 прогонов): у меня в Chromium средняя точка около 2.7 мс, формула около 3.1 мс на серию из 12 радиусов, повторённую 500 раз. Первый прогон в обоих случаях медленнее остальных, а разница между способами сравнима с разбросом между прогонами, поэтому уверенного вывода о скорости из этого делать нельзя.
